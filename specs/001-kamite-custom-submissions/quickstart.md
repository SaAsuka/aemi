# Quickstart: 動作確認の手順

テスト環境（`vozel-test` のデプロイ先・テストDB）で行う。本番では行わない。

## 準備

1. マイグレーションをテストDBに適用済みであること（research R11）
2. テスト用タレントを2人用意: **A**（名前・生年月日・身長・コンポジットあり）、**B**（身長未登録・コンポジットなし）
3. KAMITE送信用スクリプト `scripts/send-test-kamite-job.ts`（実装タスクで作る。テスト環境の `KAMITE_API_KEY` / `KAMITE_API_SECRET` で署名して送る）
4. ユニットテスト: `npm test`（`detectAutofill` / 項目キー / 再送時の引き継ぎ / 回答の検証（1件ずつ） / 未提出の判定 / アップロード失敗の分類 / 受付番号 / 本人の決定ロジック / 報告を送り直すかの判定 / 年齢の計算 / ZIP内のファイル名）

## シナリオ

### S1. KAMITE案件の提出項目が応募フォームに出る（US1・US2・US3）

以下の requirements で送信:
```json
[
  { "label": "お名前", "kind": "TEXT", "required": true },
  { "label": "年齢", "kind": "TEXT", "required": true },
  { "label": "身長", "kind": "TEXT", "required": true },
  { "label": "近影写真（正面）", "kind": "PHOTO", "required": true, "note": "メイクなし・自然光で" },
  { "label": "最寄駅", "kind": "TEXT", "required": true },
  { "label": "参考動画", "kind": "URL", "required": false },
  { "label": "プロフィール資料", "kind": "FILE", "required": true },
  { "label": "プロフィール写真", "kind": "PHOTO", "required": false },
  { "label": "保護者氏名", "kind": "TEXT", "required": false }
]
```
期待:
- 案件の説明文に提出物の文章が**出ない**
- タレントAで開くと7項目が順番どおり（プロフィール資料・プロフィール写真は出ない）。お名前・年齢・身長が埋まっていて、年齢は書き換え不可
- 「保護者氏名」は空欄（タレントの名前で埋まらない）
- 最寄駅を空で応募 → 最寄駅の下に理由、そこまでスクロール、他の入力は残る
- 近影写真にPDFを選ぶ → 受け付けない
- **5MB以上のiPhone写真**を近影写真に上げる → 進み具合が出て成功する（4.5MB問題の回避確認）
- 名前と身長を書き換えて応募 → 完了。応募の回答は書き換えた値、**プロフィールの名前・身長は元のまま**
- 生年月日が未登録のタレントで開く → 年齢が空の入力欄で出て、入力すれば応募できる
- 応募フォームを開いたまま、案件の項目を変えて KAMITE から送り直す → 応募すると「案件の内容が更新されました。画面を開き直してください」。開き直すと入力が戻っている

### S2. 管理画面で確認・一括ダウンロード（US4）

- 応募管理一覧 → 「内容を見る」で `/admin/applications/[id]`
- 項目順に回答、写真はサムネイル、プロフィール資料・プロフィール写真の行に「コンポジット（登録済みのもの）」としてタレントのコンポジットが出る、参考動画は「未提出」
- 管理画面でタレントAのコンポジットを作り直す → 応募詳細のコンポジットも新しいものになる（回答には保存していないため）
- 「写真をまとめてダウンロード」→ ZIP の中のファイル名が `{タレント名}_近影写真（正面）.jpg`

### S3. 本人確認（FR-018）

- タレントAでログインしたまま、開発ツールで `talentId` を B のIDに書き換えて応募 → **Aとして**応募される（Bの応募は作られない）
- 開発ツールで `status=ACCEPTED` を送る → 応募の状態は「応募中」
- ログアウト状態で応募処理を直接呼ぶ → 拒否される。`form_error_logs` には**記録されない**（開発者向けのログにだけ出る）
- 他人の `applications/{BのID}/...` のURLを `/api/blob` で開く → 403（タレントA）／表示できる（管理者）
- 専用リンク（`/jobs/{id}?t=...`）から応募 → トークンの本人として応募される
- 管理画面の代理応募 → 今までどおり選んだタレント・状態で応募できる
- **S1 の案件（必須の自由項目あり）に管理画面から代理応募** → エラーにも「開き直してください」にもならず応募できる。応募管理一覧で「未提出あり」になり、応募詳細で管理者が回答を入れられる

### S4. コンポジットなし（US3）

- タレントBで開く → 応募ボタンが押せず案内が出る
- 開発ツールでボタンを有効にして送信 → 拒否される
- 管理画面の代理応募でBを選ぶ → **今までどおり応募できる**（代理応募にはコンポジット必須を課さない）

### S5. 既存の動きが変わらない（US5・最優先）

- 管理画面で「課題演技動画」だけ設定した案件を作成 → タレントで応募 → 今までと同じ見た目・保存結果
- この機能より前の応募を管理画面で開く → 今までどおり提出物リンクが出る
- 案件編集で自由項目「最寄駅（文字・必須）」を足す → 応募フォームに出る。順番入れ替え・削除が反映され、既存の応募の回答は残る

### S6. KAMITE再送（Edge）

- S1の案件を、「最寄駅」を消して「最寄りのバス停」を足して再送 → フォームは新しい項目。S1の応募の回答（最寄駅）は管理画面で残っている
- 再送の前に、管理画面で「プロフィール写真」の自動判定を「なし」に直しておく → 応募フォームに写真の欄として出る。再送後も「なし」のまま（管理者の修正が引き継がれる）

### S7. エラーの記録（US6）

- 機内モードにして写真をアップロード → 「通信の問題」と出て、その項目だけやり直せる。受付番号が表示される
- **止まったとき**: 大きな写真のアップロード中に開発ツールの通信制限で止める（または途中で機内モード）→ 30秒で自動で中止され「通信の問題」。アップロード中の「中止」ボタンでも止められる
- **送信が終わらないとき**: 応募の送信を開発ツールで遅延させる → 30秒で操作が戻り、応募済みなら完了画面、未完了なら入力が残ったまま「もう一度送信」。再送しても応募は1件だけ。「あとで別途送る」の項目がある応募で1回目が成功していた場合、再送後の完了画面にも別途送る案内と受付番号が出る
- **削除時**: 自由項目の回答がある応募を削除・そのタレントを削除 → 今までどおり成功し、既存の提出物・宣材写真・コンポジットのファイルは今までどおり消える。自由項目のファイルはストレージに残る（決定どおり）
- **報告が届かないとき**: 機内モードのままアップロードを失敗させる → 受付番号は表示される → 機内モードを解除して次の操作をする → `/admin/error-logs` にその番号の記録が届いている
- `POST /api/form-errors` をログアウト状態で呼ぶ → 401（記録されない）。短時間に31件送る → 31件目は 429
- 文字を入力 → 画面を再読み込み → 入力が戻っている。応募済みの案件を開き直すと途中保存は消えている
- 必須の近影写真のアップロードを失敗させ、「あとで別途送る」を選んで応募 → 完了画面に「近影写真は管理者に別途送ってください（受付番号：E-XXXXXX）」
- 一度もアップロードしていない必須項目では「あとで別途送る」が出ない。開発ツールで `ans_{key}_deferred=1` を送っても未入力扱いで応募できない
- 応募管理一覧に「未提出あり」の印、「未提出ありのみ」で絞り込むと件数・ページ送りが合っている → 応募詳細で「別途送付待ち」が目立つ → 管理者が写真を登録 → 「管理者が登録」と日時が出て、印が消える
- `/admin/error-logs` に S1〜S7 で起きた失敗が日時・タレント・案件・項目・理由つきで並び、受付番号で検索できる。入力値は記録されていない

### S8. 端末

- iPhone Safari・LINE内蔵ブラウザ・Android Chrome で S1 の写真アップロードと応募が通る（カメラ・ライブラリ両方）

## 合格の目安

S1〜S8 がすべて期待どおり、`npm test` と `npx tsc --noEmit` が通る。そのうえで山中さんにテスト環境で触ってもらう（SC-008）。
